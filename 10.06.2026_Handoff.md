# GSCO Environmental Tool — Engine Handoff

**Date:** 10 June 2026
**Scope:** Current state of the screening engine (`engine/`) and how it fits the wider tool.
**Companion docs:** `HANDOFF.md` (journey/benefits overview), `CLAUDE.md` (working rules), `docs/Indicators_Audit_and_v1x_Roadmap.md` (the authority for all v1.x indicator decisions), `Updating_the_Code.md` (what the GSCO team must maintain over time).

> This is a point-in-time snapshot of *how the engine works today*. It does not change any decision; where it summarises a methodology choice, the authoritative source is the relevant `docs/` file (and, for v1.x, the audit doc).

---

## 1. The one-paragraph summary

The engine takes a site or region (an "AOI"), a time window, and a set of selected indicators, and produces a scored environmental screening across three pillars — **Air → GHG → Nature** — plus a composite traffic-light, per-indicator confidence, and a full provenance trail for every number. The architecture is **"Option D": stateless pillar function libraries + one thin stateful orchestrator.** Each pillar (`air.py`, `ghg.py`, `nature.py`) is a flat library of `compute_*` functions with no memory between calls; the orchestrator (`ScreeningRun`) is the only stateful object and is the single entry point the UI uses. All six engine milestones and all UI pages (P-01 → P-11) are built and live. Current work is **v1.x refinement** (calibration, indicator re-grammaring, doc reconciliation), not initial construction.

## 2. Architecture at a glance

```
engine/
├── orchestrator.py     ScreeningRun — the ONLY stateful class; UI entry point
├── air.py              Air Pollution pillar  (9 pollutants + sub-aggregates)   ← stateless
├── ghg.py              GHG pillar            (CH₄, VIIRS, CO₂/ODIAC)            ← stateless
├── nature.py           Nature/Land pillar    (biodiversity, habitat, vegetation)← stateless
├── constants.py        EVERY tunable number lives here (no magic numbers in pillars)
├── ids.py              Canonical indicator IDs
├── verbal_summary.py   Deterministic prose generator (no LLM)
├── parameter_registry.py  Tracks tunable parameters + their calibration status
├── exceptions.py       IndicatorComputeError / PillarComputeError hierarchy
└── core/               Reusable stateless building blocks (see §6)
```

**Pillar order is fixed: `air → ghg → nature → composite`.** The UI, the verbal summary, and the CSV exports all assume this order. GHG deliberately runs *after* Air because it borrows two Air sub-aggregates (the industrial-combustion proxy and the smoke/dust transport term). Air and Nature have no cross-dependency and run concurrently.

**Why stateless pillars + thin orchestrator?** The pillar functions take inputs and return a result dict with no side effects, so their formulas can be tested with synthetic payloads (no Earth Engine needed). All the genuinely stateful concerns — accumulating results, catching partial failures, assembling the composite — live in one place: the orchestrator.

---

## 3. The orchestrator (`engine/orchestrator.py`)

`ScreeningRun` is the single class the result pages instantiate. It:

1. Runs each pillar (Air + Nature concurrently, then GHG so it can read Air's results).
2. Accumulates every indicator's output into one `payload` dict.
3. Catches `PillarComputeError` per pillar → renders the **partial-result UI** instead of failing the whole run (Wireframes P-05 "S2_Partial"). A single dead indicator (`IndicatorComputeError`) is recorded in a failures list and the rest of the run continues — **no silent defaults**; a missing value is `None` and is surfaced.
4. Computes the **composite** as the equal-weighted mean of the three pillar follow-up priorities, and **composite confidence** as the minimum of the three pillar confidences. Both use strict-`None` propagation: if any pillar is missing, the composite is `None` rather than a guessed number.

`TrendRun` and `PrioritisationBatch` are referenced as the planned siblings of `ScreeningRun`; screening is the fully-built mode today. Trend analysis runs as a **post-screening drill-down** (see §6, `trend.py`), never inside the screening composite.

## 4. The repeatable core — how a single indicator is scored

Most indicators ("temporal" ones: the 9 air pollutants, CH₄, NDVI) go through the **six-step method** in `engine/core/repeatable_core.py` (`six_step`):

1. **Site value** — mean of the band over the Site_Buffer (a small circle around the point).
2. **Background value** — median + standard deviation over the Background_Ring (an annulus around the site, land-masked so a coastal ring doesn't read the ocean).
3. **Anomaly & z-score** — `anomaly = site − background_median`; `z = anomaly / σ`. *How surprising is this, in units of normal variability?*
4. **Hotspot frequency (HF)** — the fraction of distinct days in the window whose z crossed the 2σ threshold. *How often, not just how much.*
5. **Score** — `clamp(anomaly / (k·σ), 0, 1)` with `k = 3`. The 0–1 severity used by the traffic light; a 3σ exceedance saturates to red.
6. **Confidence** — a 4-term formula (data-quality / number-of-valid-days / anomaly-strength / spatial-context) × a "column-to-surface" defensibility multiplier.

**Important nuance — the σ denominator (M-DIAG-A4).** The standard deviation used in steps 3–5 is **not** the spatial spread of the ring. It is the **temporal σ of the site's own day-to-day values over a trailing "clean" window before the screening period** — i.e. "how much does this site normally vary day to day?" This was a deliberate fix: the old spatial σ was 2–14× too small and inflated false anomalies. It is computed **live on every run** (nothing stored). VIIRS is excluded from this temporal denominator (stably-lit sites have near-zero temporal variance) and keeps a spatial σ.

**`z` vs the `score`:** same numerator and same σ — the score is just `clamp(z/3, 0, 1)`, directional and bounded. `z` answers "is this real?"; `score` answers "how bad, for the dashboard?".

## 5. Indicators by pillar

### Air (`engine/air.py`) — the z-score grammar
Nine single-value pollutants, all via `six_step`:

| Indicator | Source asset |
|---|---|
| NO₂, SO₂, CO, HCHO, O₃, AAI | Sentinel-5P (`COPERNICUS/S5P/OFFL/L3_*`) |
| PM₂.₅, PM₁₀ | CAMS (`ECMWF/CAMS/NRT`) |
| AOD | MODIS MAIAC (`MODIS/061/MCD19A2_GRANULES`) |

These roll up through fixed-weight **sub-aggregates** (e.g. industrial-combustion proxy = 0.6·NO₂ + 0.4·CO) into the Air pillar score. Weights live in `engine/constants.py`. **Wind attributability** (M-WIND-A1) tags NO₂/SO₂/HCHO/AAI/AOD anomalies as high/moderate/low/sparse using ERA5 wind on the exact anomaly days — it is categorical context only and does **not** feed the score or confidence.

### GHG (`engine/ghg.py`) — a mix of grammars, by design
- **VIIRS night-lights** — the **live severity signal**, redesigned under **M-GHG-REDESIGN-A1**. It does **not** use the z-score path. Instead it produces two outputs: a **flaring severity** (fraction of site pixels brighter than an absolute ~100 nW anchor, normalised) and a **lit-contrast attributability** (the site's brightness percentile within its ring). This is sustained-activity *stock*, not a transient anomaly — do not "unify" it back onto the z-score path.
- **CH₄ (methane)** — **demoted to reference/context** (M-CH4-A1): TROPOMI's ~7 km footprint is too coarse to attribute methane at site scale, so it is not scored in the live composite.
- **CO₂ (ODIAC)** — **reference/context only** (M5.5b): a modelled annual inventory with a 2+ year vintage lag, so it can't score a recent 90-day window. It displays as context when the window falls in its coverage (2020–2023).

> Net effect: the *live* GHG severity is combustion-proxy (borrowed from Air) + VIIRS flaring. CH₄ and CO₂ still appear in payloads as context — easy to misread as "scored," but they are not.

### Nature (`engine/nature.py`) — mixed grammars
Three scored composite terms feeding the Nature follow-up priority:
- **Biodiversity exposure** — KBA proximity + sensitive land cover + water/wetland exposure.
- **Habitat conversion** — Dynamic World land-cover composition now vs. 5 years earlier; the decrease in natural-class fraction is "natural loss," apportioned to built/bare/crop and annualised. (See the dedicated explanation we keep in chat history — it's a buffer-level fraction comparison, a documented v1 approximation, not per-pixel transition mapping.)
- **Vegetation condition** — NDVI inverted-anomaly + low-vegetation area − recovery signal.

Reference layers (not scored into the composite): **Hansen forest loss** (now feeds `regional_loss_evidence`, the ring-vs-buffer "is this loss regional or supplier-specific?" check), KBA, water mask, Dynamic World class confidence.

> **M-V1x-RECONCILE / Hansen demotion:** per the audit doc, Hansen's cumulative-since-2000 framing was removed from the live habitat composite because it breaks the live-window semantics of the Dynamic-World terms. `docs/Indicators_Audit_and_v1x_Roadmap.md` is the authority for this and all other v1.x indicator decisions.

## 6. The `engine/core/` toolbox

| Module | What it provides |
|---|---|
| `repeatable_core.py` | The six-step method; server-side hotspot-frequency; the M-DIAG-A4 temporal-σ denominator; the M-FALLBACK-A1 recovery composition. |
| `normalisation.py` | The 0–1 score clamp (`to_score`). |
| `confidence.py` | The 4-term per-indicator confidence formula. |
| `buffers.py` | Site_Buffer + Background_Ring geometry, with MOD44W land-masking (M-TIER-A3). |
| `climatology.py` | The **per-country fallback** baseline (median ± σ) used when a ring is unusable — reads the stored `demo/climatology.json` fixture. *(Distinct from the live temporal σ above.)* |
| `fallback.py` | Decision logic for SPPY (same-period-previous-year) and climatology recovery (M-FALLBACK-A1), with confidence penalties. |
| `wind.py` + `era5.py` | Wind attributability for air indicators (categorical context). |
| `attributability.py` | Categorical high/moderate/low/sparse attributability (habitat centroid offset; VIIRS lit-contrast). |
| `trend.py` | Theil–Sen slope + Mann–Kendall significance for the **post-screening trend drill-down only** — never enters the screening composite. |
| `provenance.py` | The canonical provenance block every indicator emits (M5.6). |
| `adaptive_scale.py` | Picks the reduceRegion scale by AOI size so region-scale runs don't blow EE pixel limits. |
| `ee_resilience.py` / `ee_safety.py` | Retry-with-backoff on transient EE errors; guards against empty-collection crashes. |

## 7. Two kinds of "baseline," don't confuse them

This trips people up, so it's worth stating plainly:

| Mechanism | What it is | Updated how? |
|---|---|---|
| **Climatology σ denominator** (M-DIAG-A4) | The temporal σ of the site's own per-day series over the trailing clean window — the *normal-path* denominator for z and score. | **Never manual** — recomputed live from Earth Engine every run. |
| **Climatology fallback** (M-FALLBACK-A1, `demo/climatology.json`) | A stored per-country median ± σ, substituted *only* when a background ring is unusable (e.g. AOI over water). | **Stored fixture, vintage-stamped** — refreshed ~annually by re-running a tool. See `Updating_the_Code.md`. |

## 8. Provenance & the "no silent defaults" rule

Every single-value indicator emits a `_provenance.<pillar>.<indicator>` block built via `engine.core.build_provenance` (M5.6, schema in `docs/provenance_schema.md`). A missing value is always `None` and surfaced in a failures list — the engine never substitutes a default to fill a gap. When a fallback fires, it is recorded loudly (e.g. `clim_baseline_applied`, the fallback confidence penalty, the fixture `vintage`), so any number that leaned on a recovery path declares it.

## 9. Tests

Tests live in `tests/` and split into:
- **Synthetic-payload unit tests** — exercise the formulas with plain numbers, no Earth Engine. This is where the maths is pinned (six-step, normalisation, confidence, fallback decision logic, composite/rollup).
- **EE integration tests** — run the full path against real assets on known demo sites.
- **Milestone regression tests** — each major methodology change (M-DIAG-A4, the VIIRS redesign, M-PERF, etc.) ships with a regression test that locks the new behaviour.
- **UI/page tests** — component and page-flow coverage for P-01 → P-11.

**Convention (CLAUDE.md §7):** every new `compute_*` function gets a synthetic-payload test *first*. Don't skip it.
